# DriveIQ internationalisation (i18n)

## Supported locales

| Code | Language |
|------|----------|
| `en` | English (default) |
| `hi` | Hindi (हिन्दी) |
| `mr` | Marathi (मराठी) |

Stored in `localStorage` key `driveiq_locale`. Detected from browser language on first visit when possible.

## Usage in components

```tsx
import { useT } from "@/i18n/use-locale";
import { LanguageSwitcher } from "@/components/language-switcher";

function Example() {
  const t = useT();
  return <h1>{t("home.heroTitle")} {t("search.found", { count: 12 })}</h1>;
}
```

## Where the switcher appears

- Public header (landing, search, about, …)
- Login / register
- School, admin, instructor, learner portal headers

## Adding strings

1. Add key under the right namespace in `frontend/src/i18n/locales/en.ts`
2. Mirror in `hi.ts` and `mr.ts` (TypeScript enforces shape)
3. Use `t("namespace.key")` in the UI

## Coverage status

| Area | Status |
|------|--------|
| Shell nav / footer / portal sidebars | Done |
| Home marketing sections (keys ready; wire remaining copy via `t()`) | Partial — hero + shared keys |
| Auth pages | Done (login) / partial (register chrome) |
| Search filters | Keys in catalog; page still has some hardcoded English — replace with `t("search.*")` |
| Deep dashboard page bodies | Incremental — use same `t()` pattern |
| API error messages | Server English for now |

## Product-wide rule

**No new user-visible English string without a catalog key** for chrome and primary flows. Page-specific content migrates file-by-file using the same catalogs.
