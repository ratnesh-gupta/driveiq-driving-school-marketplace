# Backend Security Audit (Phase 1, audit only)

Scope: `backend/` (Laravel 13.9.0, PHP 8.3, Sanctum 4.3.2) as of 2026-10-31, commit `f05d3cb`. No application code, migration, config or test was changed. Line numbers refer to the files at audit time. `composer audit` was run (network available). Findings are grounded in code that was read; items I could not exercise at runtime (no live server, no queue worker) say so.

Severity: Critical = exploitable now, fix before anything else; High = fix before pilot launch (M11); Medium = hardening sprint; Low = hygiene / defence in depth. Effort: S (under 0.5 day), M (1-2 days), L (3+ days or cross-team).

Totals: 1 Critical, 3 High, 13 Medium, 11 Low (28).

## Verified OK

Checked in code and found sound (cite is the evidence; "exposure" notes mean I looked for the weakness and did not find it).

AuthN / AuthZ
- Route coverage: all 177 `api/*` routes listed with `php artisan route:list --json`; every authenticated route sits in `auth:sanctum` with a `role:` group (`routes/api.php:135-337`); no mutating route is unauthenticated without a named throttle (15 public POSTs, all throttled: `routes/api.php:50-53,80-81,85,91,96-99,107,110,112,115,119`).
- `SchoolAccess` is called in every `{schoolId}` and child-resource action of Learner, Instructor, Vehicle, Schedule, Progress, Payment, Billing, Subscription (school-scoped), Settings, Dashboard, Analytics, Stats, GoogleBusiness, Team, Document controllers (verified by reading each action; the only actions without it are `me`, `plans`, `skillsCatalog` and admin-only ones behind `role:admin`).
- IDOR/BOLA: every `/{id}` child route resolves the model with `withoutGlobalScope('school')` then authorizes against the model's `school_id` (Vehicle, Schedule, Payment, LeadNote, Convert, Document, Instructor); missing rows answer 404, foreign rows 403. Learner self-access (`allowSelf`) compares `user_id`; trainer access requires assignment or a shared session (`SchoolAccess.php:126-139`).
- Foreign ids in bodies use `SchoolScopedIds` (`LearnerController.php:90-92,609-613`, `ScheduleController.php:107,157`, `ProgressController.php:60`) and `ScheduleService::assertNoConflicts` re-checks instructor/vehicle school membership under row locks.
- Mass assignment: no `create/fill/update($request->all())`; all writes map explicit keys. `User::$fillable` contains `role`/`school_id` but all five `User::create` calls pass literals (`AuthController.php:20-25`, `ListingClaimService.php:124-129`, `InstructorController.php:176-182`, `LearnerController.php:578-584`, `SchoolTeamController.php:165-170`); registration accepts only `school|learner` (`RegisterRequest.php:18`). School verification flags, `rating`, `review_count` and `slug` are stripped for non-admins (`UpdateSchoolRequest.php:103-117`); `listing_status` is written only by admin/system via `forceFill`.
- Owner vs manager: `ownerOnly: true` on team invite/remove, Google Business connect/import/disconnect, billing request/cancel, package delete, trainer terminate, owner audit trail (`SchoolTeamController.php:47,206`, `GoogleBusinessController.php:47,57,73,104`, `BillingController.php:48,72`, `PackageController.php:75`, `InstructorController.php:298`, `SchoolDashboardController.php:184`).
- Tokens: expiry 7 days (`config/sanctum.php:55`), deactivated users rejected at the guard (`AppServiceProvider.php:45-47`), logout deletes the current token, password reset deletes all tokens (`AuthController.php:121-130`), deactivation and manager removal delete tokens; reset broker expiry 60 min, throttle 60 s; forgot-password answers uniformly.
- Invite flow: invite token is 48 random chars, only the SHA-256 is stored, 7-day expiry, nulled on accept/revoke, existing accounts must be signed in as the invited email, managers cannot be admins/instructors/other schools (`SchoolTeamController.php:80-86,147-158,251-273`).
- Claim flow: token `Str::random(48)` (about 285 bits), hash-only storage, 30-day expiry, single use, other links deleted on claim (`ListingClaimService.php:43-52,148`); 6-digit code via `random_int`, bcrypt-hashed, 10-minute expiry, `MAX_ATTEMPTS=5` per code counted before comparison, row-locked, max 3 codes per hour per claim, attempts committed outside the main transaction so wrong guesses always count (`:74-102,115-116,173-196`), plus `public-forms` 5/min/IP. Effective guess budget is about 15 attempts per hour per claim against 10^6 codes. Ownership requires email-verified owner before publishing (`School.php` `publishBlockers`).
- Email verification and document download use signed routes (`routes/api.php:55-58,129-133`); verification compares `hash_equals(sha1(email))` on top of the signature (`EmailVerificationController.php:34-38`).

Tenant isolation
- The 7 unscoped models: `AppNotification` (every query filters `user_id`, `NotificationController.php:21-23,44-47`), `AuditLog` (owner view filters `school_id` after an owner check, admin view is admin-only), `FeaturedPlacement`, `OutboundMessage`, `PlatformInvoice` admin endpoints (admin-only routes; school views always `where('school_id', $schoolId)` after `access()`, `BillingController.php:28,38,76`), `GoogleBusinessConnection` (always `where('school_id', $id)` after an owner check; callback re-checks owner membership, `GoogleBusinessController.php:153-157`), `ListingClaim` (token hash lookup only). No cross-school read found. Recommendation is a `forSchool()` helper (see work packages), not a bug fix.
- `BelongsToSchool` fails closed for authenticated users without a school (`Traits/BelongsToSchool.php:39`). Unauthenticated/queue paths (`InquiryController::store`, `ReviewController`, `PackageController::index`, listeners, commands) were reviewed and filter explicitly or are public by design (but see BSEC-09).
- Raw SQL: all `selectRaw`/`whereRaw`/`orderByRaw` use constants or bound parameters (inventory of 40 call sites under `app/`; user-driven values are bound: `LOWER(email) = ?`, `ST_MakePoint(?, ?)`, `ST_DWithin(..., ?)`, escaped LIKE in `AdminUserController.php:26`). PostGIS search validates `nearLat/nearLng/radiusKm` numerically and binds them (`SchoolService.php:405-424`). The only interpolation is the dead `scopeNearby` (BSEC-24).
- Public listings use `School::public()` in search, show, slug, compare, featured, public trainers and outreach counts (`SchoolService.php:28,119-125,138`, `InstructorController.php:311`); `includeHidden` honoured only for admins (`SchoolController.php:25`), a school's own hidden listing is visible to its staff only (`:74`). Inquiry and review creation require a published school (`StoreInquiryRequest.php:16`).

Abuse controls, transport, files
- Named limiters exist for login/register/reset/claim/review links/consents/contact/data requests/webhook; honeypot + minimum fill time on public forms; limiter keys include email for `auth`.
- Google Ads webhook uses `hash_equals` on a string-checked key, fails closed (404) when unset, dedupes by `lead_id`, ignores test leads (`GoogleAdsLeadController.php:26-37,39-41,51-55`).
- Uploads: `file|max:5120|mimes:pdf,jpg,jpeg,png,webp` (content sniffed), server-chosen path `schools/{school}/{kind}/{owner}/{uuid}.{ext}`, display name sanitised, `belongsToSchool()` rejects foreign prefixes and `..` before serving or deleting, private disk, 5-minute signed download, `nosniff` and `no-store` headers (`DocumentStorage.php`, `DocumentController.php:98-103`). CSV import is capped at 2 MB and previewable (`AdminProspectController.php:155`). No SVG/HTML accepted.
- SSRF: the only outbound HTTP is `GoogleBusinessService` to six constant Google hosts with 10-15 s timeouts; no URL is taken from a request. Redirects: all `redirect()->away()` targets are built from `config('app.frontend_url')` plus fixed paths; claim token is `rawurlencode`d (`GoogleBusinessController.php:133`). The email-verification and OAuth redirects therefore cannot be pointed elsewhere.
- CORS: single explicit origin from `FRONTEND_URL`, credentials off (`config/cors.php`); API is bearer-token, so CSRF does not apply; sessions are not used for the API.
- `.env` is git-ignored and not tracked; `.env.example` contains no real secrets (empty keys, `driveiq` dev DB password only for local); `APP_DEBUG` defaults to false in `config/app.php:42`; prod compose sets `APP_DEBUG: "false"`.
- Webhook/outreach: unsubscribe answers uniformly and uses hashed tokens; outreach HTML uses escaped Blade, the only `{!! !!}` is the plain-text view (`outreach-text.blade.php:1`); suppression list is hash-only and checked before every send.
- Messaging: numbers validated as E.164, deduped per (template, subject, recipient hash), outbound log stores masked number + hash only (`Messenger.php:33-48`); staff WhatsApp requires the user's own `whatsapp_opt_in_at` (`User.php:92-95`); opt-in/out is written to `consents` and the audit log (`WhatsAppPreferenceController.php:50-70`).
- Billing: prices come from the `plans` table, not the client (`BillingService.php:36-38`); only the owner can request an invoice, only admins can record payment, `paid` and `void` are terminal (`assertOpen`), payments `pending` -> `paid|failed` only, locked row (`PaymentService.php:141-151`).
- Audit log: Eloquent guard blocks update/delete and the PG trigger blocks DELETE and content UPDATEs (see BSEC-17 for the gaps); school owners can read only their own school's rows.
