# Frontend Security Audit (Phase 1, audit only)

Scope: `frontend/` as of 2026-10-31 (React 19 SPA, bearer-token auth). No application code was changed. Line numbers refer to the files at audit time. `pnpm audit --prod` was run (needs registry access).

Severity: High = fix before pilot launch; Medium = fix in the hardening sprint; Low = hygiene. Effort: S (under 0.5 day), M (1-2 days), L (3+ days or cross-team).

## CSP readiness (for the FSEC-02 work package)

Proposed starting policy (deploy as `Content-Security-Policy-Report-Only` first):

```
default-src 'self';
script-src 'self' https://maps.googleapis.com;
style-src 'self' 'unsafe-inline' https://fonts.googleapis.com;   (see below)
font-src 'self' https://fonts.gstatic.com;
img-src 'self' data: blob: https://maps.gstatic.com https://maps.googleapis.com https://*.googleusercontent.com <spaces-host>;
frame-src https://www.google.com;                                 (Maps Embed iframe)
connect-src 'self' <api-origin> https://maps.googleapis.com wss://<reverb-host>;
object-src 'none'; base-uri 'self'; form-action 'self'; frame-ancestors 'none';
```

What would break and why:
- `components/ui/chart.tsx:79` and Radix/sonner/Framer Motion inject inline `<style>`/style attributes: needs `style-src 'unsafe-inline'` (or nonces; Vite does not emit them). Scripts need no inline allowance: `index.html` has only `<script type="module" src>`.
- `JsonLd` renders `<script type="application/ld+json">`; data blocks are not executed, so they are not blocked by `script-src`.
- Google Maps JS needs `script-src`, `connect-src`, `img-src`, and `frame-src https://www.google.com` for the embed (`school-map.tsx:40`). Maps also uses blob workers: add `worker-src blob:`.
- Fonts: Google Fonts link (`index.html:17-19`) needs `fonts.googleapis.com`/`gstatic`; self-hosting removes both (also fixes FSEC-06).
- Reverb: `connect-src` must list the `wss://` host from `VITE_REVERB_HOST`.
- Deliver `frame-ancestors` and `X-Frame-Options` as real HTTP headers (not meta). Also add `X-Content-Type-Options: nosniff`, `Strict-Transport-Security`, `Permissions-Policy: geolocation=(self), camera=(), microphone=()`.
- No analytics or third-party tags are present (grep of `src/` and `index.html` found none); `CookieConsent` says optional analytics may come later and must be gated on "accepted".

## Verified OK

- XSS: `dangerouslySetInnerHTML` appears twice only: `json-ld.tsx:7` (escaped, see FSEC-09) and `ui/chart.tsx:79` (CSS built from developer-defined chart config, not API data). No `innerHTML`, `eval`, `new Function`, `document.write` anywhere in `src/`. School descriptions, reviews, notes and messages are rendered as React text, so they are escaped.
- All 6 `target="_blank"` anchors have `rel="noopener noreferrer"` (`school-map.tsx:55`, `rto-office-card.tsx:56`, `government-links-section.tsx:53-54`, `legal-disclaimer.tsx:14-15`, `school-detail.tsx:506-507`); `window.open` in `documents-panel.tsx:96` nulls `opener`.
- Government and RTO link URLs come from static bundled JSON, not the API. `wa.me` link digit-only (`school-detail.tsx:505`). Maps URLs use `encodeURIComponent` (`school-map.tsx:9,40`, `schools-map.tsx:31`).
- Login `next` is sanitised and pushState-based (FSEC-15); claim `google`/`code` params are removed from the URL after read (`claim.tsx:30`, `google-business-card.tsx:40`, `dashboard/index.tsx:67`).
- No `console.*` calls in `src/` (no PII/token logging). No cookies are used or set by the app, so CSRF is not applicable to bearer-token calls. Fetch never sends `credentials`.
- 401/402 handling is centralised in `ops-api.ts:26-31` and `auth-api.ts:62-71`; 402 raises the plan-lock listener. Backend remains the authority; guards only hide UI.
- Secrets: `frontend/.env` is git-ignored and untracked (`.gitignore`, only `.env.example` tracked); it contains only `VITE_API_BASE_URL`. The only `VITE_` variables in use are API base URL, Reverb public app key (public by design) and the Maps key (public, restricted in GCP, FSEC-14). No server secret is exposed.
- Source maps: none in `dist/` (FSEC-19 only to pin).
- Realtime only subscribes to the user's own private channel and sends the bearer token to `/broadcasting/auth` (FSEC-05 covers lifecycle).
- Third party: Maps scripts load lazily only on explicit user action; no analytics, no CDN scripts in `index.html` besides Google Fonts CSS.
- Consent (DPDP): registration, claim, WhatsApp opt-in and portal acknowledgement checkboxes all default to unticked (`register.tsx:32-40`, `claim.tsx` `agree` false, `school-detail.tsx:101`); grants are POSTed to `/api/consents` (`consent.ts:84-100`, `cookie-consent.tsx:50`, `role-consent-gate.tsx:78`), with a pending retry queue. Cookie banner has equal "essential only" option. Location store persists only state/city.
- Persistence: query cache is in memory only (no persist plugin); the only storage contents are token, theme, locale, attribution UTMs, consent cache, device id, location (state/city) and compare ids (sessionStorage).
- Honeypot and anti-spam fields present on the public inquiry (limited by FSEC-17).
- Upload: signed-URL document download only; no client-rendered user HTML or SVG preview.
